# Deploying: web client on Cloudflare Pages, API and database on AWS

```
Visitor ──▶ https://foundryos.pages.dev                              Cloudflare Pages (React build)
   │
   └──────▶ https://<id>.execute-api.ap-south-1.amazonaws.com/api/v1  AWS API Gateway (HTTPS, free address)
                 │  adds X-Origin-Secret + X-Client-IP
                 ▼
            EC2 :80  Caddy (403 without the secret) ──▶ FastAPI ──▶ PostgreSQL
```

No domain or DuckDNS is needed:

- Cloudflare gives the web client `*.pages.dev`.
- API Gateway gives the API an HTTPS address.

**Why API Gateway.** A page served over `https://` may not call an `http://` server, and the EC2 server has no certificate of its own. API Gateway provides the HTTPS.

**Only API Gateway reaches the API.** Caddy rejects any request without the secret header (`ORIGIN_SECRET`, generated by Terraform). PostgreSQL and FastAPI are not published at all.

**Real visitor address.** API Gateway passes `$context.identity.sourceIp` in `X-Client-IP`, and Caddy forwards it as `X-Forwarded-For`, so sign-in rate limits work per visitor. Any `X-Forwarded-For` header sent by the visitor is ignored.

**CORS.** FastAPI allows only `FRONTEND_ORIGIN` (the Pages address).

**Limits:**

- API Gateway ends requests after **30 seconds**, so this stack sets the AI timeouts to 25–28 s.
- Traffic is throttled to 25 requests per second (burst 50).
- The free tier covers 1 million API calls per month for 12 months. After that, the cost is about US$1 per million calls.

## 1. AWS permissions (once)

The `terraform-admin` IAM user needs, in addition to `AmazonEC2FullAccess`:

1. Go to **IAM → Users → terraform-admin → Add permissions → Attach policies directly**.
2. Attach **AmazonAPIGatewayAdministrator**.

## 2. Create the server and the API address

```powershell
cd E:\foundryos-ai-module0\infra\terraform
terraform init -upgrade
terraform plan        # 8 to add
terraform apply
terraform output api_url
terraform output api_domain
```

Wait 3–5 minutes for the first-boot preparation:

```powershell
ssh -i "$HOME\.ssh\foundryos-key" ubuntu@<public_ip> "cloud-init status --wait; docker --version"
```

## 3. Publish the web client (Cloudflare Pages)

```powershell
cd E:\foundryos-ai-module0
powershell -ExecutionPolicy Bypass -File .\deploy\deploy-pages.ps1 -ApiDomain <api_domain>
```

The script:

1. asks for `PUBLIC_DEMO_PASSWORD`, which must be the same value you will put in `deploy/.env` on the server;
2. builds the app against the API Gateway URL;
3. writes the security headers (`_headers`);
4. signs in to Cloudflare once (`wrangler login`);
5. publishes the project `foundryos`.

Note the address it prints, for example `https://foundryos.pages.dev`.

## 4. Copy the code to the server

Secrets, virtual environments and build output are left out:

```powershell
cd E:\foundryos-ai-module0
tar -czf "$HOME\foundryos-src.tgz" --exclude=.git --exclude=.venv --exclude=node_modules --exclude=frontend/dist --exclude=.env --exclude="*tokens*.txt" --exclude=.terraform --exclude="*.tfstate*" --exclude="*.tfvars" --exclude=__pycache__ --exclude=.pytest_cache --exclude=.ruff_cache --exclude="*.dump" --exclude="*.pem" --exclude="*.key" .
scp -i "$HOME\.ssh\foundryos-key" "$HOME\foundryos-src.tgz" ubuntu@<public_ip>:~
ssh -i "$HOME\.ssh\foundryos-key" ubuntu@<public_ip> "mkdir -p ~/foundryos-ai && tar -xzf ~/foundryos-src.tgz -C ~/foundryos-ai && rm ~/foundryos-src.tgz"
Remove-Item "$HOME\foundryos-src.tgz"
```

Once the repository is on GitHub, `git clone` / `git pull` on the server can replace this.

## 5. Configure and start the API (on the server)

```bash
cd ~/foundryos-ai/deploy
cp .env.production.example .env
openssl rand -hex 24        # use as POSTGRES_PASSWORD
nano .env
```

Fill in the following:

| Setting | Value |
|---|---|
| `COMPOSE_FILE` | `docker-compose.aws-api.yml` (already set) |
| `FRONTEND_ORIGIN` | the Pages address, e.g. `https://foundryos.pages.dev`, with no trailing slash |
| `ORIGIN_SECRET` | on Windows: `terraform output -raw origin_secret` |
| `POSTGRES_PASSWORD` | the `openssl` output |
| `DEMO_MODE` / `PUBLIC_DEMO_PASSWORD` | `true` and the same demo password used for Pages |

Then start the stack:

```bash
docker compose up -d --build                  # first build: 5-15 min on t3.micro
docker compose ps                             # db, backend, api running; migrate exited (0)
```

Load the synthetic demo data, create your private admin, and create the demo accounts:

```bash
docker compose run --rm -e ENVIRONMENT=development backend python -m app.cli.seed --apply
docker compose run --rm backend python -m app.cli.create_admin admin --name "Plant Admin"
docker compose run --rm backend python -m app.cli.demo_accounts
```

Check from Windows:

```powershell
curl.exe -s "$(terraform -chdir=E:\foundryos-ai-module0\infra\terraform output -raw api_url)/health/ready"
```

The answer should be `{"status":"ready",...}`.

## 6. Backups and daily demo reset (on the server)

`crontab -e`, then add:

```
30 2 * * * bash /home/ubuntu/foundryos-ai/deploy/backup-db.sh >> /home/ubuntu/backup.log 2>&1
45 2 * * * cd /home/ubuntu/foundryos-ai/deploy && docker compose run --rm backend python -m app.cli.demo_accounts >> /home/ubuntu/demo-reset.log 2>&1
```

## Updating

| What changed | What to run |
|---|---|
| Frontend | Run `deploy-pages.ps1` again. |
| Backend | Copy the code again (step 4), then on the server: `cd ~/foundryos-ai/deploy && bash backup-db.sh && docker compose up -d --build`. `deploy/.env` is never overwritten. |

## Troubleshooting

| Symptom | Fix |
|---|---|
| A CORS error in the browser console | `FRONTEND_ORIGIN` must exactly match the Pages address. Run `docker compose up -d`. |
| API calls return 403 | `ORIGIN_SECRET` on the server differs from `terraform output -raw origin_secret`. |
| API calls return 503 or time out | Check that the server is running (`docker compose ps`) and that port 80 is open in the security group. |
| `terraform apply`: AccessDenied on `apigateway` | Attach **AmazonAPIGatewayAdministrator** (step 1). |
